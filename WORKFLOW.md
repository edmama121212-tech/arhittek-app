# Упрощённая карточка проекта и расчёты команды

## Что изменено

- Четыре вкладки вместо общей длинной формы: Обзор, Команда, Деньги, Документы.
- Площадь находится в основных данных проекта. Контакты и особые условия свернуты.
- Один видимый выбор каждого процентного исполнителя; второй сотрудник раскрывается отдельно.
- Новые проекты дизайна интерьера получают метод м²; архитектура и ландшафт — процент после прямых расходов (ставка категории, иначе 40%). Сохранённые проекты не меняют метод при открытии.
- В строке каждого сотрудника показаны формула и сумма. Для м² предложена редактируемая ставка 400 ₽; сохранённые начисления не пересчитываются автоматически.
- Участники на окладе добавляются без проектной доплаты. Новое начисление м²/процент сотруднику на окладе блокируется. Старые начисления не удаляются.
- План вознаграждений отделён от начисления после завершения. Оплаты клиента и остаток до общих расходов показаны отдельно.
- Защита от повторного добавления сотрудника на одну роль, двойного нажатия, начисления по несохранённой площади и переключения метода поверх записей м².
- Табель явно показывает оклад, проектную часть и остаток. Полная выплата требует подтверждения. Пользователь без прав администратора не видит финансовые вкладки и не может вызвать новые операции изменения начислений через интерфейс.

## Проверка

106 изолированных проверок Chromium: исходные финансовые сценарии плюс вкладки, шаблоны, дубли начислений, оклады, смена метода, ограничения ролей и переполнение каждой вкладки на 390/360 px. Снимки карточки проверены визуально. Рабочая база в тестах не использовалась.

## Граница этого выпуска

Это упрощение интерфейса и защита текущих операций, без миграции рабочей базы. Флаг выплаты остаётся отметкой полной выплаты месяца, а не журналом банковских переводов. Частичные выплаты, закрытие месяца, история ставок и отдельная фактическая дата завершения пока не реализованы: для них необходимы схема Supabase, авторизованные транзакции и RLS. Текущие финансовые ограничения подробно перечислены в AUDIT.md. Изменение текущих окладов или дат старых проектов по-прежнему может повлиять на исторический отчёт.

Сохраняйте основной проект перед добавлением начислений по м². Кнопки добавления начислений, расходов и платежей сохраняют операции сразу; общая кнопка сохраняет поля карточки. Старые записи автоматически не конвертируются.

## Полная проверка приложения — 11.10.2026

После изменений запускаются `npm test`, `npm run test:finance` и `npm run test:app`. CI выполняет все три набора. Дополнительный аудит проверяет большие списки, сбои сохранения, повторные нажатия, архивирование обязательств, снимки тарифов КП, публичный каталог, клиентские ТЗ и PWA. Проверки изолированы от рабочей Supabase.

При ошибке загрузки финансы показывают неполученные данные вместо подтверждённого остатка. Кнопка сохранения проекта при частичном сбое сообщает, что основная карточка уже сохранена, и просит проверить команду. Перенос проекта в корзину не является денежной операцией и сохраняет его обязательства.

Доступ к Supabase требует отдельного серверного исправления: подтверждено чтение нескольких внутренних таблиц без пользовательской сессии. Подготовлен только безопасный диагностический SQL, не миграция. Подробности и приоритеты — в `AUDIT.md`.

## Частичный объём сотрудника

Для начисления по м² добавлена «Площадь работы, м²». При открытии карточки подставляется вся площадь, можно указать меньший объём. Сохраняются сумма и формула с индивидуальной площадью в записи начисления; площадь самого проекта не меняется. Значения выше площади проекта, нулевые и отрицательные блокируются. Каждая роль может работать по той же площади (например, визуализация и чертежи). Добавлены проверки распределения 60/40 м², сохранения, дробных значений и попадания в табель только после завершения.

## Переработка вкладки команды

Убраны вложенные условия и повторные списки сотрудников. Для интерьера доступен только расчёт за индивидуальные м², сотрудники на окладе исключены из добавления. Для архитектуры и ландшафта — процент после прямых расходов. Старые условия сохраняются до явного перехода, завершённые старые расчёты не конвертируются через переключатель. Процент и сумма показаны в одной строке сотрудника. Незаполненный расчёт не выдаётся за нулевой гонорар.

Итоговая проверка этого выпуска: 121/121 изолированных браузерных сценариев. В обычных проектах выбор метода скрыт полностью: правило определяется категорией.

## Сверка всех денег компании

Финансы → Резерв → «Сверить все деньги компании». Укажите вместе наличные и счета, включая деньги проектов, невыплаченную команду и амортизацию. Сверка сохраняет фактический общий остаток отдельно от денежных операций. Приход или расход ради выравнивания не создаётся, разница с журналом остаётся видна.

После сверки обычный новый приход увеличивает деньги, оплата уменьшает. При восстановлении уже оплаченной старой операции укажите её фактическую дату; если это день пересчёта, включите отметку «Эти деньги уже входили в фактическую сверку». Это уточнит журнал без повторного движения пересчитанных денег. В остальных случаях отметка выключена.

Амортизация и доля команды находятся внутри всех денег. Закрытие проекта меняет распределение, сохраняя общий остаток. Свободный резерв рассчитывается по обязательствам журнала с 05.10.2026; старые авансы и выплаты до этой даты требуют отдельной сверки. Запускайте `npm test`, `npm run test:finance` и `npm run test:app`; проверки используют только изолированную базу.
