# ARHITTEK — приложение студии

Проекты, строительные объекты, каталог, документы, выплаты и финансы. Клиентская часть публикуется как статические файлы. Данные, права и финансовые транзакции обслуживает Supabase.

## Где работать

- `src/app/` — оболочка, загрузка данных, навигация, синхронизация и оформление.
- `src/features/` — исходники по функциям приложения.
- `src/manifest.json` — порядок сборки HTML, классических скриптов и стилей.
- `supabase/` — серверные SQL, миграции и функция клиентского доступа.
- `tests/` — изолированные проверки PostgreSQL и браузера.
- `docs/APP_MAP.md` — экраны, роли, данные и основные переходы.
- `docs/ARCHITECTURE.md` — зависимости, сборка и правила сопровождения.

Файлы HTML, JS и CSS в корне собираются из `src/`. Для изменения интерфейса найдите соответствующий раздел в карте приложения, отредактируйте исходник и выполните сборку. Сгенерированные файлы входят в Git, чтобы существующая статическая публикация могла обслуживать их напрямую.

## Работа с кодом

```sh
npm ci
npm run build
npm run build:check
```

Сборка использует стандартные модули Node.js. Она объединяет фрагменты в заданном порядке и проверяет, что каждый исходник и каждый публикуемый файл включены в манифест. `build:check` завершится с ошибкой при расхождении исходников и результата.

Для локального просмотра запустите любой статический сервер из корня проекта. Для взаимодействия с рабочими данными нужен разрешённый доступ к серверу приложения. Браузерные тесты подменяют сеть и используют учебные данные.

## Проверка изменений

```sh
npm test
npm run test:finance
npm run test:app
npm run test:ux
npm run test:construction
npm run test:security
npm run test:catalog
npm run test:catalog:pdf
npm run test:finance:workspace
```

Полный порядок проверки находится в `.github/workflows/regression.yml`. Дополнительные сценарии договоров и журнала запускаются там отдельно. Для существующего локального Chromium тесты принимают переменную `BROWSER_EXECUTABLE` с путём к исполняемому файлу.

`tests/visual-audit.cjs` снимает экраны владельца и сотрудников на учебных данных. Папку результата можно задать через `AUDIT_SCREENSHOT_DIR`, ширины через `AUDIT_WIDTHS`. Исторический `tests/construction-foreman-audit.cjs` сохраняет требования прежнего аудита. Часть его ожиданий относится к прежней модели вознаграждения и структуре вкладок. Актуальные сценарии стройки перечислены в `test:construction`.

## Работа с сервером

SQL и файлы клиентского доступа описаны в `supabase/OWNER_ACCESS.md`, `supabase/SESSION_SECURITY.md`, `FINANCE_V2.md` и `supabase/client-portal-contract.md`. Перед изменением серверной функции сверяйте её установленную версию и зависимости. Подробности установки и совместимости приведены в архитектуре.
