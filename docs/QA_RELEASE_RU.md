# ARHITTEK · результат приёмки кандидата

Исходная версия — c85be96. Изменения, проверяемый код и результаты собраны в [PR №68](https://github.com/edmama121212-tech/arhittek-app/pull/68). Все денежные примеры в тестах используют учебные записи.

## Что изменилось для руководителя

| Задача | Путь от финансовой главной | Наблюдаемый результат |
|---|---|---|
| Внести состоявшийся расход | Ещё → Записать расход | Указать назначение и сумму, проверить дату. При одном месте хранения приложение автоматически указывает «Сейф». При необходимости выбрать проект. Получателя и источник средств можно уточнить в дополнительных реквизитах |
| Запланировать будущий платёж | Ещё → Платёжный календарь → Запланировать расход | Платёж попадает в план. Отдельное действие регистрирует фактическую оплату |
| Найти проведённую операцию | Ещё → История операций | Поиск работает по названию, дате и сумме среди загруженных записей. Есть загрузка более ранних операций |
| Увидеть результат месяца | Ещё → Отчёт за месяц | Выручка, расходы и чистый доход за указанный период. Прогноз по проектам вынесен в отдельный раздел |
| Проверить деньги по проекту | Карточка проекта → Деньги → расход, затем Финансы | В 13 сценариях проверены сумма расходов за месяц и число проводок сразу и после перезагрузки |

В верхней карточке «Сейф» показан физический остаток основного хранилища. При наличии отдельных кошельков их остатки доступны в деталях. В рабочей базе по просьбе владельца изменено только название единственного активного системного кошелька, с прежней общей кассы на «Сейф». После записи отдельный запрос подтвердил новое имя. Идентификатор и проводки не менялись. Внешний вид новых экранов поставляется с обновлением приложения.

На тестовом телефоне в Chromium пройдены 12 целевых маршрутов по видимым названиям. Проверены доступ к форме, различие плана и оплаты, возврат из формы, поиск, пустая выдача и удержание клавиатурного фокуса. При повторном построении экрана раскрытые списки платежей остаются открытыми. На финансовой главной для суммы месячных расходов приложение больше не вычисляет прогноз всего портфеля проектов.

## Связанные исправления

- В форме создания и редактирования проекта виден короткий номер «№…». Серверная нумерация по направлениям сохраняет прежний формат для совместимости.
- В клиентском каталоге кнопка «3+» включает дома выше трёх этажей. Сообщение о недействительной ссылке сохраняется. Фильтры доступны с клавиатуры.
- Кабинет заказчика показывает переплаченную накладную как оплаченную и отдельно указывает переплату.
- В анкете ТЗ вопросы связаны с полями, варианты выбираются с клавиатуры и сохраняют фокус. На узком экране кнопки рабочего стола помещаются в карточке.
- Установленное приложение открывает кешированную оболочку по адресу каталога приложения при потере сети. Ссылки клиентского каталога с параметрами исключены из кеша сервис-воркера.
- В Edge раздельно проверены сохранение файла и системная отправка PDF. Ложное падение теста при открытии системного меню устранено.

## Поставка

Установочный архив WordPress собирается командой `python3 scripts/wordpress/package.py /tmp/ARHITTEK_Workspace_QA.zip`. Упаковщик проверяет соответствие 38 публикуемых текстовых файлов исходникам и включает только разрешённые ресурсы приложения. Установка проверялась в изолированном WordPress. Пакет предоставляет маршруты `/app/` и `/app/catalog/`. При наличии обычной страницы каталога WordPress она сохраняет свой маршрут. Принятие изменений в рабочую версию, активация плагина на домене и проверка после выкладки — отдельные этапы поставки.
