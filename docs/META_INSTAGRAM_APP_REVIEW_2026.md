# ARHITTEK Catalog — Meta App Review: пакет подготовки

Дата: 2026-11-23. Meta App ID: `1192662563090694`; Instagram: `@arhittek.plans`; Unified Login config: `1703509418068198`.

## Назначение

ARHITTEK управляет каталогом готовых проектов частных домов. Клиент оставляет комментарий с запросом «проект» под публикацией `@arhittek.plans`. Приложение обрабатывает событие комментария через официальный Instagram webhook, выдаёт одноразовую персональную ссылку на клиентский каталог (срок 48 часов) и отправляет **один private reply** в Instagram Direct. Форма обращения в WhatsApp доступна из каталога. Клиентам недоступно скачивание PDF-альбома.

## Минимальные разрешения (Unified Login)

- `instagram_basic`: идентифицировать подключённый профессиональный аккаунт и проверить, что события относятся к `@arhittek.plans`.
- `instagram_manage_comments`: получать события `comments` с текстом и идентификатором комментария; обрабатывать только запросы о проектах.
- `instagram_manage_messages`: отправлять private reply с индивидуальной ссылкой по `comment_id`.

**Не запрашивать:** `ads_management`, `ads_read`, `instagram_content_publish`, доступ к рекламным аккаунтам, публикацию от имени клиента или полный партнёрский контроль.

## Проверенная техническая схема

1. Meta App webhook `comments` -> `https://chbkkoxwzpaghanofvqk.supabase.co/functions/v1/instagram-catalog`.
2. GET challenge — проверка `META_VERIFY_TOKEN`, HMAC SHA-256 для POST по `META_APP_SECRET`. Secrets доступны только в Supabase Edge Function Secrets.
3. Определение ключевых слов запроса, исключение собственного комментария, проверка допустимости времени события.
4. Атомарное создание записи отправки; защита от дублей.
5. Персональная ссылка с `expires_at = created_at + 48h`.
6. Отправка Instagram private reply: `recipient.comment_id`; журнал `message_id` при успешном ответе Meta.
7. Клиентский каталог использует `get_public_catalog(token)`; сервер отвергает истёкшие/удалённые ссылки. Прямое анонимное чтение таблиц закрыто.

**Состояние на момент подготовки:** Meta callback был подтверждён, переключатель `comments` в App Dashboard — On. Реальных доставленных Direct — 0; тестовый комментарий не появился в журнале Supabase. Работа со всеми обычными клиентами НЕ подтверждена.

## Дополнительная диагностика от 23.11.2026 (без секретов)

- Webhook verification **GET уже прошёл**, поле `comments` в Meta Dashboard **On**; функция `instagram-catalog` **ACTIVE v15**, `verify_jwt=false`. Это **не** подтверждение доставки событий или действительности OAuth access token.
- По Supabase read-only: `arhittek_marketing.instagram_replies` — `total=0`, `sent=0`. В `function_edge_logs` по endpoint за ~23 часа: `GET 200×1`, `GET 403×8`, `POST 401×5`, `POST 503×2`, **POST 2xx×0**. Исторические 401/503 включают диагностические запросы, **не** доказывают, что Meta отправляла POST. Не извлекать URL query и HTTP headers из логов (могут содержать секреты).
- **Отдельный уровень подписки:** переключатель в App Dashboard и регистрация **конкретного** IG/страницы — разные проверки. Для выбранного **Unified Login** сначала безопасно проверить через авторизованный Meta API, поддерживает ли текущий тип OAuth-токена `GET https://graph.facebook.com/v27.0/17841422845904072/subscribed_apps`; передавать token исключительно заголовком `Authorization: Bearer …` из секретного окружения, не параметром URL и не в логах. Если endpoint не поддерживается, **не** переключаться автоматически на Facebook Page или Instagram Login, не добавлять `pages_*` и не менять портфолио/партнёрские права. Свериться с документацией точного выбранного Meta use case. Любая подписка `POST` выполняется лишь после проверки применимости endpoint/прав; `DELETE` запрещён.
- Meta в официальном [руководстве для Instagram Webhooks](https://developers.facebook.com/docs/graph-api/webhooks/getting-started/webhooks-for-instagram/) прямо отмечает необходимость **Advanced Access/App Review для `comments`** в описанном там режиме. Это руководство описывает также Page subscriptions старого Graph API; нельзя автоматически переносить требования `pages_manage_metadata` на Unified Login. Фактически у данного приложения три `instagram_*` пока только «Готово к тестированию», приложение **не опубликовано**. Поэтому прежде чем создавать ещё комментарии, нужно проверить режим приложения и допустимость реальной доставки в используемом Unified Login.
- **Meta API read-only checklist (без раскрытия токена):** подтверждение `/me?fields=id,username` или эквивалентного IG профиля; выяснение `subscribed_apps` у нужного аккаунта; HTTP status и безопасный набор **имён** выданных permissions без полного токена/ответа; сравнение account ID. Не делать никаких отправок сообщений, пока webhook и авторизация не подтверждены.
- **Реальные скринкасты App Review не подготовлены**, потому что тестовый комментарий ещё не достиг обработчика. Юридические данные для Privacy Policy / data deletion также **не подтверждены**, выдумывать нельзя. Не подавать заявку с фиктивным роликом. После исправления подписки/режима — один свежий комментарий от другого разрешённого IG tester на публичном медиа; затем контролировать ровно один webhook, `message_id` и Direct в клиентском приложении.
